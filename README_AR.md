# خلاصة المفيد – KHOLASAT AL MOFEED

تطبيق Full-Stack عربي لتنظيم فيديوهات القنوات التعليمية التي يختارها المستخدم، مع مكتبة شخصية، مجالات، مجلدات، متابعة المشاهدة، بحث، وجيمناوي عبر Gemini.

> **هذه حزمة السورس كود نفسها، وليست Prompt.** ارفع محتويات المجلد إلى مستودع GitHub جديد، أو شغّلها محليًا. GitHub يحفظ الكود ولا يشغّل خادم Node.js أو قاعدة البيانات؛ النشر العام يحتاج لاحقًا بيئة تشغيل Node.js وتخزينًا دائمًا.

## 1) ما الذي تم تنفيذه في هذه النسخة؟

### واجهة المستخدم
- واجهة عربية RTL متجاوبة للهاتف والكمبيوتر، مع شاشة استقبال ودخول بالاسم أو كضيف.
- الرئيسية، الاستكشاف، المجالات، القنوات، صفحة الفيديو، جيمناوي، الملخصات، المفضلة، المشاهدة لاحقًا، سجل المشاهدة، المجلدات، الملف الشخصي، الإعدادات، ولوحة المالك.
- بحث داخلي في فيديوهات وقنوات مكتبة المستخدم، وبحث YouTube خارجي منفصل لا يضيف نتائجه تلقائيًا إلى الرئيسية.
- مشغل YouTube الرسمي عبر IFrame Player API.
- حفظ تقدم المشاهدة دوريًا عند تشغيل الفيديو، مع استئناف آخر موضع محفوظ.
- المفضلة، المشاهدة لاحقًا، إنشاء المجلدات، وإضافة الفيديوهات للمجلدات.
- الإعدادات الأساسية تحفظ في قاعدة البيانات، مع إعدادات للمظهر والأقسام والإشعارات والأداء.
- تصدير بيانات المستخدم بصيغة JSON وحذف بياناته.

### Backend وقاعدة البيانات
- خادم Express API.
- SQLite محلية دائمة في `data/kholasat.sqlite`، تُنشأ تلقائيًا عند تشغيل الخادم.
- جداول منفصلة للمستخدمين، القنوات، الفيديوهات، ربط المستخدم بالقنوات، المفضلة، المشاهدة لاحقًا، سجل المشاهدة، تقدم المشاهدة، المجلدات، الملخصات، المحادثات، الإشعارات، الإعدادات، وسجل استهلاك API.
- التحقق من المدخلات الأساسية، تحديد معدل طلبات API، Helmet، حماية لوحة المالك بملف Cookie موقّع من الخادم.
- مزامنة خادمية مجدولة كل 3 ساعات أثناء استمرار تشغيل عملية Node.js.

### YouTube وGemini
- YouTube Data API v3 لجلب القناة وآخر الفيديوهات والبحث الخارجي.
- لا يتم إضافة فيديوهات البحث الخارجي إلى الرئيسية تلقائيًا.
- جيمناوي يتصل بـ Gemini من الخادم فقط، ويكتشف موديلًا يدعم `generateContent` ويستبعد Preview/Experimental افتراضيًا قدر الإمكان.
- التلخيص يتطلب نص تفريغ أو وصفًا كافيًا؛ لا يتم اعتبار رابط YouTube وحده دليلًا على مشاهدة الفيديو.
- مفاتيح API لا توجد في ملفات الواجهة ولا في المستودع؛ تُقرأ من Environment Variables.

## 2) متطلبات التشغيل

- Node.js إصدار 20 أو أحدث.
- npm.
- لا تحتاج PostgreSQL أو Redis أو Replit أو Render لكي تشغّل نسخة التطوير على جهازك.
- لا تحتاج YouTube أو Gemini لكي تفتح الواجهة؛ تحتاج مفاتيحهما لتفعيل تكاملهما الفعلي.

## 3) التشغيل المحلي

من جذر المجلد:

```bash
npm install
```

انسخ `.env.example` إلى ملف جديد باسم `.env`، ثم غيّر الأسرار:

```env
PORT=3000
NODE_ENV=development
DATABASE_FILE=./data/kholasat.sqlite
ADMIN_PASSWORD=ضع_كلمة_مرور_طويلة_هنا
SESSION_SECRET=ضع_سرًا_عشوائيًا_طويلًا_هنا
ADMIN_SESSION_SECRET=ضع_سرًا_مختلفًا_هنا
YOUTUBE_API_KEY=
YOUTUBE_DAILY_QUOTA_BUDGET=10000
GEMINI_API_KEY=
GEMINI_MODEL=
GEMINI_FALLBACK_MODEL=
```

شغّل الواجهة والخادم معًا:

```bash
npm run dev
```

افتح عنوان Vite الذي يظهر في الطرفية (غالبًا `http://localhost:5173`). الخادم يعمل على `http://localhost:3000` والواجهة تمرر `/api` إليه عبر Proxy.

## 4) بناء نسخة الإنتاج وتشغيلها

```bash
npm run build
npm start
```

سيخدم Express ملفات الواجهة من `dist`، ويشغّل API من العملية نفسها. على نظام استضافة يدعم متغيرات البيئة، اضبط `NODE_ENV=production` و`PORT` واحتفظ بمجلد `data/` على قرص دائم.

## 5) إعداد YouTube API

1. أنشئ مشروعًا في Google Cloud Console.
2. فعّل YouTube Data API v3.
3. أنشئ API Key، وقيّده بحسب قيود Google المتاحة.
4. ضع المفتاح في `YOUTUBE_API_KEY` على الخادم فقط.
5. أعد تشغيل الخادم.

العمليات التي تستخدم `search.list` تستهلك وحدات Quota أعلى من طلبات جلب التفاصيل. يسجل التطبيق العمليات التي نفذها داخليًا في جدول `api_usage`، لكنه لا يقرأ رقم الحصة المتبقية الفعلي من Google؛ راجع Google Cloud Console للحصة الرسمية.

## 6) إعداد Gemini API

1. أنشئ مفتاحًا من Google AI Studio / Gemini API.
2. ضعه في `GEMINI_API_KEY` على الخادم فقط.
3. اترك `GEMINI_MODEL` فارغًا للاكتشاف التلقائي، أو ضع اسم موديل صالحًا يدعم `generateContent`.
4. يمكن ضبط `GEMINI_FALLBACK_MODEL` لموديل احتياطي صالح.
5. افتح صفحة جيمناوي لاختبار إرسال سؤال. ويمكن للمالك فحص الموديل من لوحة المالك.

## 7) لوحة المالك

- اضبط `ADMIN_PASSWORD` و`SESSION_SECRET` و`ADMIN_SESSION_SECRET` بقيم قوية ومختلفة.
- افتح `/admin` من داخل التطبيق.
- كلمة المرور لا تُحفظ في Frontend؛ يتم التحقق منها على الخادم وتصدر جلسة Cookie موقعة وHttpOnly.
- لا تضع ملف `.env` أو أي مفاتيح حقيقية داخل GitHub.

## 8) رفع الملفات إلى GitHub يدويًا

1. فك ضغط ملف ZIP على جهازك.
2. افتح GitHub وأنشئ Repository جديدًا فارغًا باسم `kholasat-al-mofeed`.
3. استخدم **Add file → Upload files**.
4. اسحب محتويات مجلد `kholasat-al-mofeed-source` إلى صفحة الرفع (لا ترفع مجلد `node_modules` ولا ملف `.env`).
5. اضغط Commit changes.

يمكن أيضًا استخدام Git من جهاز به Git:

```bash
git init
git add .
git commit -m "Initial Kholasat Al-Mofeed source"
git branch -M main
git remote add origin https://github.com/USERNAME/kholasat-al-mofeed.git
git push -u origin main
```

استبدل `USERNAME` باسم حسابك. لا تضع رمز GitHub الشخصي داخل ملفات المشروع.

> **تنبيه:** رفع الملفات إلى GitHub لا ينشر الموقع ولا يشغّل الـBackend. GitHub Repository هو مستودع للكود. لن يعمل التطبيق للجمهور حتى تختار لاحقًا استضافة تدعم Node.js، وتضع متغيرات البيئة، وتضمن قرصًا دائمًا لقاعدة SQLite. لا توجد عملية نشر خارجية أو تسجيل دخول إلى حسابك ضمن هذه الحزمة.

## 9) قاعدة البيانات والنسخ الاحتياطي

- قاعدة البيانات تنشأ تلقائيًا عند بدء الخادم.
- المسار الافتراضي: `data/kholasat.sqlite`.
- خذ نسخة من ملف SQLite بعد إيقاف الخادم أو باستخدام نسخة احتياطية متوافقة مع SQLite.
- SQLite مناسبة لنسخة أحادية الخادم/المثيل. إذا احتجت توسعًا أفقيًا أو عدة خوادم متزامنة، انقل التخزين إلى PostgreSQL وأضف طبقة ترحيل بيانات قبل تشغيل عدة مثيلات.
- بيانات الضيف مرتبطة بمعرف UUID محفوظ في متصفح المستخدم. هذا ليس تسجيل دخول آمنًا ولا يزامن الحساب بين الأجهزة.

## 10) الاختبار

```bash
npm run check
npm run build
```

- `npm run check` يفحص Syntax ملفات الخادم باستخدام Node.js.
- `npm run build` يفحص تجميع React/Vite.
- اختبر يدويًا تدفق إضافة قناة، المزامنة، المشغل، المفضلة، المجلدات، الإعدادات، محادثة Gemini، وحماية `/admin` بعد إضافة مفاتيح صالحة.

لا تعتبر تكامل YouTube أو Gemini ناجحًا قبل تجربة مفتاح صالح وحدود الحصة الفعلية. لا تعتبر نشر الإنتاج مكتملًا قبل التأكد من استمرار البيانات بعد إعادة تشغيل الخادم.

## 11) حدود هذه النسخة بوضوح

هذه نسخة Full-Stack أساسية قابلة للتشغيل والتطوير، وليست ادعاءً بأن جميع المواصفات الموسعة في الـMaster Prompt نُفذت بالكامل. وظائف مثل Telegram وWhatsApp وTikTok، المسارات التعليمية التكيفية، الاختبارات وFlashcards المتقدمة، الملخصات اليومية، تحليلات التعلم المتقدمة، استيراد JSON، وتكاملات النشر والنسخ الاحتياطي المُدارة تحتاج تطويرًا واختبارًا إضافيين. أي وظيفة غير موجودة في الواجهات أو API لا ينبغي اعتبارها جاهزة.
